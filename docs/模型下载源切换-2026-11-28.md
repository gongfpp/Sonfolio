# 模型下载源切换到 ModelScope（2026-11-28）

## 现象

朋友在国内网络（移动数据）安装 Debug APK 后，在「选择模型」页点「下载并启用」失败，界面显示：

```
failed to connect to huggingface.co/31.13.64.7 (port 443) from /10.87.100.3 (port 44530) after 20000ms
```

四个模型（SenseVoice、Qwen3-ASR、FireRedASR2-CTC、Qwen2.5-0.5B）在国内网络下全部无法下载。

## 根因

三层问题叠加，最上面那层只是症状。

**一、hf-mirror.com 已停止直链镜像。** 2026-11-28 实测：

| 请求 | 结果 |
| --- | --- |
| `GET https://hf-mirror.com/` | `200`，静态首页正常 |
| `GET https://hf-mirror.com/<repo>/resolve/<rev>/<file>` | `308` → `https://huggingface.co/...` |
| `GET https://hf-mirror.com/api/models/<repo>` | `308` → `https://huggingface.co/...` |

换任意仓库（包括 `openai-community/gpt2`）、不带代理直连，结果一致。首页能打开容易造成"镜像还活着"的误判，但下载链路已经不存在。

**二、huggingface.co 在国内被 DNS 污染。** `31.13.64.7` 属于 Facebook 的地址段，不是 Hugging Face 的服务器。TCP 握手因此永远失败，`connectTimeout = 20_000` 正好对应报错末尾的 `after 20000ms`。

**三、镜像优先 + 重定向跟随的组合放大了故障。** `downloadFrom` 会跟随 301/302/307/308，于是"镜像源"的第一跳被 308 送回境外；备用源又是同一个 huggingface.co。两个源实际是同一条死路，用户被多等了一个 20 秒。

此外，错误信息是把 `HttpURLConnection` 的英文异常原样塞进界面（`ModelDownloadWorker.kt` 的 catch 块），连运营商内网地址 `10.87.100.3` 都显示出来了，对使用者没有任何可操作信息。

## 替代源调研

| 候选 | 结果 |
| --- | --- |
| ModelScope（阿里，modelscope.cn） | **可用**。四个模型都有第三方镜像，实测下载 6.7–8.0 MB/s |
| hf-mirror.com | 失效，全部 308 跳回上游 |
| aifasthub.com | 同样 308 跳回上游 |
| hf-api.gitee.com | API 返回 200，但 resolve 路径 404，不能下大文件 |
| mirror.sjtu.edu.cn / tuna / ustc / nju | 没有 Hugging Face 模型镜像目录，路径全 404 |
| gitcode.com/hf_mirrors | 返回 206 但 content-type 是 text/html，是伪装的成功响应 |
| GitHub Releases | 三个 ASR 模型的 tar.bz2 都在（206 可达），但需要整包解压，且走境外 CDN，速度不稳定 |
| ModelScope 上的 k2-fsa / csukuangfj 官方账号 | 没有完整模型，但 `csukuangfj/FireRedASR2-AED-onnx` 的 `ctc/` 目录有单文件 |

## 采用的源

全部固定到 40 位提交号，避免镜像仓库后续更新导致文件漂移。

| 模型 | 主源（ModelScope） | 备用 |
| --- | --- | --- |
| SenseVoice Small | `mariolux/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17@99b4224` | `WEAAEW/...@59ee0bc` |
| Qwen3-ASR 0.6B（6 个文件） | `bujidc/sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25@c0ceb54` | `fjqz177/...@c3d0262`、`jkman2023/...@fb4dfc8` |
| FireRedASR2-CTC | `csukuangfj/FireRedASR2-AED-onnx@17b436e` 的 `ctc/` | — |
| Qwen2.5-0.5B GGUF | `Qwen/Qwen2.5-0.5B-Instruct-GGUF@4537f71` | — |

上游 Hugging Face 保留为最后一跳，仅供有代理的用户使用。

## 校验证据

每个镜像文件都与 `ModelCatalog` 里既有的 SHA-256 逐一比对，**不是只看文件名或大小**：

| 文件 | 大小 | SHA-256 |
| --- | --- | --- |
| `mariolux` 的 `model.int8.onnx` | 239,233,841 | `c71f0ce0…2cd51` 一致（全量下载，35.8 s，6.7 MB/s） |
| `Qwen/Qwen2.5-0.5B-Instruct-GGUF` 的 GGUF | 491,400,032 | `74a4da8c…7a9db` 一致（全量下载，61.1 s，8.0 MB/s） |
| `bujidc` 的 `tokenizer_config.json` | 12,487 | `4942d005…ea26c4c` 一致 |
| `csukuangfj` 的 `FireRedASR2/ctc/tokens.txt` | 79,172 | `1bc613de…1e5ea07b` 一致 |

其余大文件（Qwen3-ASR 三件套、FireRed 主模型）核对了字节数完全一致，并确认 ModelScope 支持 `Range` 请求（`302 → 206 Partial Content`），断点续传可用；同时用 Android 默认 UA 复测未被拦截。

## 代码改动

- `ModelCatalog.kt`：下载源改为 ModelScope 优先、固定提交号、移除 hf-mirror；Qwen3-ASR 许可链接从 huggingface.co 换成 modelscope.cn（后者在国内打得开）。
- `ModelDownloadWorker.kt`：
  - 新增 `downloadFailure()`，把 `UnknownHostException` / `ConnectException` / `SocketTimeoutException` / `SSLException` / `IOException` 分别翻译成可操作的中文，不再上屏英文原文与内网地址；
  - 所有源都失败时给出"N 个下载源均不可用：<原因>"，而不是只报最后一跳；
  - 连接超时 20 s → 10 s。
- `TranscriptionSettingsCard.kt`：连通性自检的兜底提示同样不再透传英文网络异常。
- 新增 `ModelCatalogTest`：断言每个文件首选源是 ModelScope、不含 hf-mirror、镜像地址必须是 40 位提交号、全部 https。这条测试是为了让同类回归在 JVM 阶段就被拦住。

## 验证

- `assembleDebug`、`assembleQa`、`lintDebug` 通过。
