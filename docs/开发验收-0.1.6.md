# 声迹 0.1.6 开发与验收记录

本轮于 2026-09-12 继续开发，修复搜索结果和输入被静默截断的问题，版本为 `0.1.6 / versionCode 7`。检查发现上一版查询固定只接收前 4 个关键词，SQL 又有 `LIMIT 100`，界面却把返回数量显示为全部命中数量，没有后续查看入口。本次不改数据库结构、不替换录音或推理服务，也没有新增后端、网络上传、删除或迁移已有记录；Room Schema 仍为 1。上一版文档所说的“完整列表查询”适用于时间线与原音，不能据此认为旧版搜索没有数量限制。

搜索条件现在由代码生成 SQL 结构，用户文字全部绑定为参数，所有空格分隔的关键词都必须在当前命中转写或对话标题中出现。中文全角空格及不换行空格也会分词，重复词去重；最多接受 32 个不同关键词和 512 个字符，超过时显示具体原因，不截取前面一部分继续搜索。`%`、`_`、反斜杠与单引号按字面处理，空查询加“全部”仍不列出记录；“今天”“本周”和“仅标记”维持原有筛选含义，标记覆盖命中的完整 Conversation，不因多次标记重复生成搜索结果。

界面先展示 100 条，数据库多取一条用于判断是否还有结果；尚有内容时显示“已显示 100 条相关内容 · 还有更多”，并在列表末尾提供“加载更多”，全部显示后才使用“找到 N 条”的文案。每次加载扩大 100 条读取范围，等待期间保留已显示列表并暂时禁用重复加载，按开始时间和转写 ID 排序，避免相同时间戳导致无确定次序。搜索返回后保留已加载范围和滚动状态，换关键词或筛选时重新从首批开始；这属于有界读取范围逐步扩大，不是游标分页，海量历史查询的扫描与索引优化仍待后续工作。
