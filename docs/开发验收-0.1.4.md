# 声迹 0.1.4 开发与验收记录

本轮从 2026-09-11 的暂停交接恢复，目标是补齐近期反馈中的录音反馈、标记、搜索、设置和回放，并修复会影响录音可靠性的实现问题。客户端版本更新为 `0.1.4`，Room Schema 仍为版本 1，没有清库或修改原始音频格式。既有录音、标记和转写保留；原有 `.workbuddy/` 与竞品调研文档不属于本轮改动。

录音每 5 分钟切片，中途每 5 秒更新可播放的 WAV 文件头并同步文件，首页据此显示真实文件大小。模型计算已迁入非导出 `:inference` 进程，主进程通过绑定服务发送本地文件路径和时间窗，接收识别结果；模型退出或内存不足只形成该段处理失败，队列不取消其他音频。ASR 结果和会话整理在同一事务提交，避免首页出现“原音消失但对话尚未出现”的中间状态；会话 ID 沿用已有值，跨切片更新能继续打开原详情。异常恢复结束时间来自 PCM 数据长度，缺口显示在首页，恢复不会根据刚刚被修改的 WAV 文件时间误算缺失时段。

回放使用独立的对话时间与文件偏移映射，一份音频只出现在播放序列中一次，进度条松手后定位，暂停保留位置；搜索命中也携带转写 ID 进入详情定位。结构化转写默认折叠，3/10/20 分钟标记向前回溯，再覆盖命中的整段连续对话，顶部直接显示高亮时长。短录音只有有效人声时长和文字数量同时低于阈值才隐藏，标记豁免，原音入口区分未识别、已过滤和处理失败。设置使用真实容量和可保存的语言/过滤/充电处理配置，已移除虚假状态和空操作按钮；首装不再插入演示对话。

当前标题与总结属于本地规则及提取式整理：先识别常见主题，再从实际转写选择要点、决定、安排、问题，信息量大的对话才显示重点整理，一日回顾按日期保存并提供历史日期入口。它不会凭空补人物或结论，也不是生成式日记模型。原音保留目前支持永久、7 天和 30 天提醒，到期仍由用户决定；三类音频独立保留、自动清理、降噪、说话人识别、生成式日记和全天锁屏压力测试仍未完成，不能把它们计入本次完成项。

构建命令在 `android/` 目录执行 `./gradlew --no-daemon --no-watch-fs -Pkotlin.compiler.execution.strategy=in-process :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug`。本机可复用 `GRADLE_USER_HOME=/private/tmp/sonfolio-gradle-home`；Android 调试签名位于 `/Users/mass/.android`，首次生成测试签名需要该目录写权限。真机安装两个 APK 后，用 `adb shell am instrument -w -r -e class com.gongfpp.sonfolio.PipelineIntegrationTest com.gongfpp.sonfolio.test/androidx.test.runner.AndroidJUnitRunner` 运行隔离数据与模型测试；长录音测试单独指定 `RecordingReliabilityTest`，会新增并保留实际测试录音，开始前要求没有用户正在进行的录音。

9 月 11 日晚用户开放远程点击后继续验收。MIUI 仍会拦截测试框架从后台打开页面，需在测试开始时从前台打开匹配的 MAIN/LAUNCHER Intent，不能将框架启动受限误记为客户端闪退。UI 测试改为点击导航标签，避免默认合并语义树中找不到图标描述；导航和播放器所用的次级底色也统一为声迹浅绿，去掉默认紫色。手机当前 `animator_duration_scale=0.0`，录音波形遵循系统关闭动画设置，未擅自修改手机全局配置。

故障注入还发现服务连接与推理等待不能共用一个超时：冷启动进程在建立连接前退出时不保证收到断开回调，原先会长时间等待；内部超时若直接作为取消异常向上传递，也可能使该段一直显示处理中。客户端现在分别限制连接等待 30 秒、模型处理 8 分钟，把自身超时转换为可重试失败，同时保留外部取消语义，并在结束时释放绑定。长录音测试先完成一次实际模型调用再注入推理进程故障，避免把尚未连接的启动竞态当作推理崩溃。

本轮通过 11 项单元测试及 7 项真机测试（5 项处理链路、1 项界面导航、1 项长录音可靠性），构建与 Lint 完成，0 errors / 13 warnings。实际录音和强制结束产生的录音及缺口记录保留，已有用户录音未删除。短时后台及五分钟切片不能替代全天锁屏、耗电发热和存储接近满载验收；这些仍是后续可靠性验证，不计入本轮通过项。
