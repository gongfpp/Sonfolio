设置 → 用量记录原有「近 6 个月调用次数」和「本月明细」，只统计次数、音频秒数和 token，不做金额。
本次补上累计口径与人民币估算：卡片顶部新增「本月」「累计」两行，并用估算费用替换柱状图的默认维度。

## 统计口径

| 项目 | 来源 | 说明 |
| --- | --- | --- |
| 调用次数 | 收到成功响应后计数 | 失败、超时、被取消的请求不计入，但服务商可能仍计费 |
| 音频秒数 | 本地切分窗口时长 | 识别按秒计费，与文本长度无关 |
| token | 响应体 `usage.prompt_tokens` / `completion_tokens` | 输入与输出分开累计，才能真正按单价算钱 |
| 估算费用 | 记录当时按单价表计算 | 以 1e-6 元为单位累加，避免浮点漂移 |

费用在**调用发生时**计算并累加，历史金额不会因为之后调整单价表而变化。这样 DeepSeek 这类峰谷定价
可以按真实调用时刻结算，代价是单价表调整只影响之后的调用。

## 不给估算的情况

- **订阅制**（OpenCode Go 的 deepseek-v4.1-flash、glm-5.3-flash）：按套餐额度计费，没有按 token 的单价。
- **自定义或未收录模型**，以及硅基流动 TeleSpeechASR：没有可核实的公开单价。
- **升级前的旧记录**：只有 token 总数，没有输入输出拆分，无法反推金额。

以上都只累计 token 与次数，并在明细里标为「未计价」，界面不显示猜测的金额。

## 已知偏差

- 失败或超时请求可能被服务商计费，这里不计入，因此**估算通常偏低**。
- 未考虑赠送额度、批量折扣、缓存命中优惠；DeepSeek 缓存命中的输入价（0.05–0.3 元）远低于未命中价。
- 只统计本机发起的调用，多设备或直接在网页端、命令行产生的费用不在其中。
