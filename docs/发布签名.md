# Android 发布签名

官方 Release 使用独立发布证书，不使用 Android 自动生成的 Debug 证书。私钥和密码只保存在维护者机器的私密目录；源代码中只有读取配置的逻辑。

## 首次建立

仅在没有现有发布证书时运行以下命令。目录必须位于仓库外，脚本会拒绝覆盖已有材料。

```sh
JAVA_HOME=<JDK_17_目录> node scripts/create-release-key.mjs <私密签名目录的绝对路径>
```

生成 `sonfolio-release.p12` 和 `signing.properties`，采用 RSA 3072 位、SHA256withRSA，证书有效期 30 年。目录权限为 700，文件权限为 600；随机密码不会出现在命令行参数或终端输出中。`signing.properties` 含密码，必须与私钥同等保护。请将整个目录加密备份到独立位置，并确认能够恢复；同一硬盘上的副本不能防止硬盘损坏。

## 构建

在 `android/` 目录执行：

```sh
SONFOLIO_SIGNING_PROPERTIES=<私密签名目录>/signing.properties \
  ./gradlew --no-daemon :app:assembleRelease
```

也可用 Gradle 属性 `-PsonfolioSigningProperties=<配置文件绝对路径>` 传入路径；不要直接通过参数传密码。没有配置时仍能构建未签名 APK，便于其他贡献者自行构建，但未签名产物不可发布为官方安装包。

发布前使用 Android SDK 的 `apksigner verify --verbose --print-certs <APK>` 验证签名，并与首次发布证书指纹比对。签名通过仅说明安装包身份与完整性，不代替功能、隐私和兼容性验收。

## 更新与用户数据

同一个正式发布渠道持续使用同一套签名材料。丢失私钥或密码可能导致无法向已安装用户提供覆盖更新，不要每次打包重新生成证书。

开发期手机安装的是 Debug 签名，不能直接覆盖为独立 Release 签名。不得为完成安装测试擅自卸载现有 App；先验证数据导出与恢复，或使用独立测试设备验收 Release，避免丢失录音和文字。

## GPL 源码与发行内容

本项目采用 `GPL-3.0-only`，没有非商业限制。每次正式发布 APK 时，应同时提供与该二进制对应的源码获取入口及必要构建说明，明确对应的提交和版本。不能仅提供一个不断变化的默认分支链接。

检查源码归档中是否包含实际构建所需的 Git LFS 内容，而不是仅有指针；对所用第三方原生库逐项核对版本、许可证和对应源码。GitHub 自动生成的源码压缩包不能未经核验就视作完整的对应源码。APK 中的项目许可文件由 `app/src/main/assets/licenses/sonfolio/` 随构建打包，必须与仓库根目录的 `LICENSE` 保持一致；第三方许可声明继续保留。

提供用户自行构建与安装的方法，不要求其取得维护者的发布私钥。发布证书、API Key 和用户数据不得放进源码包。源码与第三方归属完整性验收通过之后，才上传正式 Release。

参考：[Android 官方应用签名说明](https://developer.android.com/studio/publish/app-signing)。
