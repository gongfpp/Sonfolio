# Sonfolio 客户端原型

这是根据 `design/prototypes/sonfolio-v0.1-summary-flow.png` 还原的 Sonfolio 客户端原型与 Android V0.1 实现。Web 目录用于视觉对照，`android/` 是正式的本地优先客户端：录音、VAD、ASR、对话合并、搜索和原音回听都在手机端完成，不依赖后端或外部 API。

## 本地预览

在项目目录运行（如果 `4173` 被其它本地原型占用，使用 `4174`）：

```bash
python3 -m http.server 4173
# 若 4173 被占用：
python3 -m http.server 4174
```

然后打开 <http://127.0.0.1:4173>。当前环境中 `4173` 已被其它本地页面占用，本次 Sonfolio 预览使用 <http://127.0.0.1:4174>。

## 已还原的界面

- 声迹时间线：录音状态、3/10/20 分钟标记、处理中的原始对话卡片、主题标题和一日回顾入口。
- 对话详情：本段小结、结构化字段、原始转写展开、星标时间戳和播放状态。
- 详细总结：信息量较大的对话按讨论主题、关键观点、共识与决定、未决问题展示。
- 一日回顾：日记式一日总结、值得记住、可能需要处理和重新生成；它从首页的“一日回顾”卡片进入，不占用底部导航栏。
- 搜索：关键词输入、筛选、匹配内容和结果进入详情。
- 录音与存储：录音服务、容量估算、保留策略、原始录音导出、中文优先识别和可配置的短录音过滤。

原型界面会根据屏幕宽度自动切换为移动端全屏或桌面端手机壳预览。

## Android 客户端工程

`android/` 是正式客户端的 Kotlin + Jetpack Compose 工程，包含 Today、Conversation、Search、Settings 和 Daily 页面。Room 本地数据库保存 `AudioChunk -> SpeechSegment -> Transcript -> Conversation -> DailyJournal` 链路以及标记和录音缺口；首页、详情、搜索和每日回顾均从同一份数据库状态刷新。

`0.1.4` 使用 5 分钟物理切片，录音中每 5 秒刷新 WAV 文件头和已保存大小；切片完成后，WorkManager 驱动独立 `:inference` 进程中的 Silero VAD 与 SenseVoice int8，录音服务继续运行。对话按相邻语音间隔不超过 2 分钟合并，整理过程使用事务并保留已有会话 ID，跨切片更新不会重新创建正在阅读的会话。首页即时显示原音及处理状态，失败可重试，未识别和短录音过滤结果都能在“原始录音”中回听、导出。

标记支持回溯 3/10/20 分钟，命中后高亮整段连续对话，顶部显示高亮时长；目前依据时间连续性，不宣称语义主题分割。播放器固定在详情底部，支持暂停续播、拖动和从搜索/转写定位，文件内时间与对话时间分别计算。中文优先及双阈值过滤可持久化设置，实际存储占用按录音数据计算；保留期限当前实现为到期提醒，不自动删除，人声和标记仍引用完整原音，尚未实现三类音频的独立生命周期。

`0.1.5` 增加按日期浏览：切换前后日期或打开日历，时间线、原音入口及一日回顾跟随所选日期；跨午夜的对话保留完整回听，当天时长只计算实际保存于当天的音频。首页显示已保存时长、原音数量及已知缺口，处理卡片显示当日进度。搜索和底栏页面保留输入、筛选及滚动状态，详情按实际来源返回；时间线、搜索结果、原音列表和长转写采用按需布局。时间线和原音查询仍读取完整列表，尚未引入数据库分页。

`0.1.6` 修复搜索只取前 4 个关键词、结果截断为 100 条且没有后续入口的问题。空格分隔的关键词逐个参与匹配，支持中文全角空格和字面搜索 `%`、`_`、反斜杠；超过 32 个不同关键词或 512 个字符时明确提示，不静默丢弃输入。搜索先显示 100 条，尚有命中时标注“还有更多”，可继续加载；加载期间保留已显示结果和当前位置，返回搜索后保留已加载范围。这仍是逐步扩大读取范围，并非游标分页或全文索引。

每段小结、信息量较大时的重点整理和分日期一日回顾使用本地提取式规则，包含原句中的要点、决定、安排和问题，不等同于生成式 AI 日记。原始音频没有网络上传通道，并禁用系统自动备份。最新构建及待验收项见 [0.1.6 开发与验收记录](docs/开发验收-0.1.6.md)，日期浏览说明见 [0.1.5 记录](docs/开发验收-0.1.5.md)，此前真机录音证据见 [0.1.4 记录](docs/开发验收-0.1.4.md)；旧版真机通过不能替代新版界面验收，也不代表完成全天锁屏录音验收。

```bash
cd android
./gradlew :app:assembleDebug
```

模型和 arm64 native 运行库由 Git LFS 管理；从全新工作区构建前先执行 `git lfs pull`。

安装 Debug APK：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

完整的技术选型、数据边界和分阶段实现顺序见 [`docs/technical-selection.md`](docs/technical-selection.md)。
